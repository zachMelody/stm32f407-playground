# Quality Guidelines

> Code quality standards for STM32F407 embedded C development.

---

## Overview

This project uses C (C99/C11) with the STM32 HAL library. Code is generated by STM32CubeMX with user additions between `USER CODE` markers.

---

## Required Patterns

### Header Guards

Every header MUST use include guards with the `__FILENAME_H__` pattern:

```c
// From Core/Inc/gpio.h:21-22
#ifndef __GPIO_H__
#define __GPIO_H__
// ... content ...
#endif /*__ GPIO_H__ */
```

### C++ Compatibility

All headers MUST wrap declarations for C++ compatibility:

```c
// From Core/Inc/gpio.h:24-26
#ifdef __cplusplus
extern "C" {
#endif
// ... declarations ...
#ifdef __cplusplus
}
#endif
```

### HAL Init Sequence

Main initialization follows a strict order:

```c
// From Core/Src/main.c:64-89
int main(void) {
    HAL_Init();              // 1. HAL library init
    SystemClock_Config();    // 2. Clock tree setup
    MX_GPIO_Init();          // 3. Peripheral init (one per module)
    // ... user code ...
    while (1) { }            // 4. Infinite main loop
}
```

### Peripheral Init Pattern

Each peripheral gets a generated `MX_*_Init()` function with zero-initialized config struct:

```c
// From Core/Src/gpio.c:42-61
void MX_GPIO_Init(void) {
    GPIO_InitTypeDef GPIO_InitStruct = {0};  // Zero-init first
    __HAL_RCC_GPIOH_CLK_ENABLE();            // Enable clocks
    // ... configure pins ...
    HAL_GPIO_Init(GPIOB, &GPIO_InitStruct);
}
```

## Forbidden Patterns

| Pattern | Why |
|---------|-----|
| Writing user code outside `USER CODE` markers | Gets overwritten on CubeMX regeneration |
| `malloc`/`free` in main loop | Heap fragmentation in long-running embedded systems |
| Blocking delays in ISRs | Interrupt latency kills real-time behavior |
| `printf` in fault handlers | May hang if system state is corrupted |
| Magic numbers without defines | Use named constants for pin numbers, prescalers, etc. |
| Unused variables / functions | Compiler warnings, code rot |
| Global variables without `static` | Pollutes namespace across translation units |

---

## Coding Style

- **Doxygen comments** on functions: `@brief`, `@param`, `@retval` (matches STM32 HAL style)
- **Indentation**: 2 spaces (matches CubeMX generated code)
- **Variable naming**: CamelCase for HAL struct fields (`GPIO_InitStruct`), snake_case for local variables
- **Constant naming**: UPPER_SNAKE_CASE for defines (`GPIO_PIN_2`, `RCC_OSCILLATORTYPE_HSI`)

---

## Testing

This is a learning project with no automated test framework. Testing is done via:

1. Build verification: `cmake --build build/`
2. Flash to hardware: via ST-LINK debugger
3. Manual verification: observe LED behavior, check debugger output

For future: consider adding Unity or CppUTest for unit testing hardware-independent logic.

---

## Code Review Checklist

- [ ] User code within `USER CODE` markers
- [ ] HAL return values checked (`!= HAL_OK`)
- [ ] No magic numbers (use HAL defines)
- [ ] Header guards present
- [ ] `extern "C"` guards in headers
- [ ] No blocking calls in ISRs
- [ ] Peripheral clocks enabled before init
