# JBC210 / JBC245 热电偶计算取值调研

Updated: 2026-05-10

## Scope

面向当前 `LED_F407` 任务 `adc2-thermocouple-window-sampling`，梳理公开开源 JBC210 / JBC245 焊台项目里可验证的热电偶温度换算取值，并明确哪些值只能当参考，哪些值可以直接指导当前实现边界。

## Verified Sources

1. 本仓库内 `.research/AxxSolder/README.md`
2. 本仓库内 `.research/AxxSolder/AxxSolder_firmware/Core/Src/main.c`
3. OSHWLab / 立创开源平台项目 `350W 功率闭环焊台 T12-JBC210-245-470`

## Verified Findings

### 1. AxxSolder 不是用单一 `uV/C` 常量做最终温度

AxxSolder 的公开 README 和源码都表明，它的最终温度链路是：

1. 热电偶 ADC 原始值做异常值抑制
2. 再做移动平均
3. 按手柄类型套不同二次拟合式
4. 再做 6 点温度校准修正

对应源码里的公开系数：

* `C210 / T210`
  * `Temp_C210 = 4.223931712905644e-06 * ADC^2 + 0.31863796444354214 * ADC + 20.968033870812942`
* `C245 / T245`
  * `Temp_C245 = -4.735112838956741e-07 * ADC^2 + 0.11936452029674384 * ADC + 23.777399955382318`

这组系数在 README 的公开拟合式中也有对应的四舍五入版本：

* `Temp_C210 ~= 4.22e-6 * ADC^2 + 0.32 * ADC + 20.97`
* `Temp_C245 ~= -4.73e-7 * ADC^2 + 0.12 * ADC + 23.78`

### 2. AxxSolder 对 `T210` 和 `T245` 明确分开建模

公开文档明确写了：

* JBC 不同 cartridge 的 thermocouple output 不同
* 必须识别 handle type
* 需要分别使用对应的 thermocouple correction

这说明：

* `T210` 和 `T245` 不适合共用一个“最终温度换算常量”
* 用一个统一的 `41 uV/C` 去覆盖 `JBC210 + JBC245`，只能是 bring-up 级粗略估算

### 3. AxxSolder 的最终精度依赖二次拟合之后的 6 点校准

公开文档给出的校准点是：

* `100 / 200 / 300 / 350 / 400 / 450 C`

软件做法是：

* 先用二次式得到名义温度
* 再按上述 6 点做分段线性修正

所以 AxxSolder 的“最终显示温度”并不是单纯由上面的二次式直接决定。

### 4. 公开的 JLC `T12-JBC210-245-470` 项目没有暴露明确换算系数

公开项目页能确认的只有：

* 支持 `JBC210 / JBC245 / JBC470`
* 支持“实时显示采样到的发热芯热电偶原始数据”
* 支持 `180Hz` 智能恒温

但当前公开页面没有直接给出：

* `JBC210` 的温度拟合系数
* `JBC245` 的温度拟合系数
* 冷端补偿公式
* 多点标定表

因此，至少在当前公开证据下，不能把这个 JLC 项目的“真实换算取值”说成已经确认。

## Direct Implications For LED_F407

### 1. 当前工作区已经从纯 `uV/C` 临时模型，进入 `T210` 参考拟合过渡态

当前 `thermocouple_sampler.c` 的状态是：

* `tc_uv` 仍然按已知模拟增益从 `adc_mv` 反推，继续作为调试观测值
* `temp_c_x10` 已经不再直接由 `41 uV/C` 驱动
* 当前温度输出改为使用 `T210` 的参考二次拟合

这说明当前工作区已经从“纯 bring-up 常量换算”走到了“借用开源参考拟合”的过渡阶段。

这条链路适合：

* 验证 `ADC2` 通路是否通
* 验证“关断加热 -> 稳定 -> 采样 -> 恢复”窗口是否工作
* 先观察 `T210` 条件下的参考温度趋势是否合理
* 同时保留 `raw / adc_mv / tc_uv / temp_c_x10`

这条链路仍然不适合：

* 宣称为当前板子的最终真实 tip temperature
* 直接复用于 `T245`
* 跳过后续分手柄标定

### 2. AxxSolder 的二次式不能直接当成当前板子的真值

虽然 AxxSolder 也使用 `OPA2387`，但它的二次式是针对“它自己的模拟前端 + ADC 标度 + 采样时序 + 指定 cartridge 样本”拟合出来的。

因此：

* 可以把它当作“公开开源项目里已验证的参考建模方式”
* 不能在没有本板实测数据的前提下，直接宣布这些系数就是 `LED_F407` 当前硬件的最终系数

### 3. 对当前任务更合理的分层建议

第一阶段：

* 继续保留当前 `raw / adc_mv / tc_uv / temp_c_x10` 输出
* 明确标注当前 `temp_c_x10` 属于 `T210 reference fit`
* 不把它写成当前板子的最终标定温度

第二阶段：

* 按 `T210` 和 `T245` 分开采集实测点
* 至少记录 `25 / 100 / 200 / 300 / 350 / 400 / 450 C` 对应 `ADC raw`
* 先拟合每种手柄自己的 `ADC -> Temp` 曲线
* 再加多点修正表

如果在第二阶段前必须做一个“比 `41 uV/C` 更接近开源实践”的过渡版本，应优先：

* 引入“按手柄区分”的温度模型边界
* 但把模型名明确标为 `reference_fit` 或 `borrowed_fit`
* 不要命名成 `temperature_c` 或 `real_temperature_c`

## Recommended Wording In Code / Logs

建议统一使用下面这种表述，避免完成度误导：

* `temp_tmp`
* `reference_fit_temp`
* `cold_junction_fixed`
* `not_calibrated`

避免直接使用：

* `actual_temp`
* `real_tip_temp`
* `measured_temperature`

## Bottom Line

对“开源 JBC210 / JBC245 焊台的热电偶计算取值”这件事，目前能被公开证据支持的结论是：

* 开源项目 AxxSolder 对 `T210` 和 `T245` 使用不同二次拟合式，而不是共享一个固定 `uV/C`
* 最终温度还叠加 6 点校准修正
* 当前 JLC 开源项目页面只公开了“显示原始热电偶数据”和“闭环控制能力”，没有公开可直接复用的换算系数
* 当前工作区已经引入 `T210` 参考二次式作为过渡模型，但它仍然不是 `LED_F407` 当前硬件的最终取值
